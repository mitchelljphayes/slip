# slipd API Reference

Base URL: `http://<slipd-host>:7890` (configurable; default `http://localhost:7890`)

## Authentication

slipd uses two authentication mechanisms:

| Mechanism | Scope | Header |
|-----------|-------|--------|
| **HMAC (per-app deploy key)** | Deploy webhook (`POST /v1/deploy`) | `X-Slip-Signature: sha256=<hex>` |
| **Bearer token (admin)** | Management endpoints | `Authorization: Bearer <token>` |

### HMAC signature (deploy webhook)

The deploy key is a per-app secret generated by `slip key`. The HMAC is computed over the **raw JSON body bytes** using SHA-256:

```bash
PAYLOAD='{"app":"myapp","tag":"sha-abc1234"}'
SIGNATURE=$(echo -n "$PAYLOAD" | openssl dgst -sha256 -hmac "$SLIP_DEPLOY_SECRET" | awk '{print $2}')
curl -X POST "${SLIPD_URL}/v1/deploy" \
  -H "Content-Type: application/json" \
  -H "X-Slip-Signature: sha256=${SIGNATURE}" \
  -d "$PAYLOAD"
```

### Bearer token (admin)

The admin token is set in the slipd config (`auth.secret`). Pass it as a Bearer token:

```bash
curl -H "Authorization: Bearer $SLIP_TOKEN" "${SLIPD_URL}/v1/deploys/${DEPLOY_ID}"
```

## POST /v1/deploy

Trigger a new deploy. This endpoint is authenticated via **HMAC** (per-app deploy key), **not** the admin Bearer token.

### Request

```
POST /v1/deploy
Content-Type: application/json
X-Slip-Signature: sha256=<HMAC-SHA256 hex>
```

**Body:**

```json
{
  "app": "myapp",
  "tag": "sha-abc1234",
  "images": {
    "worker": "ghcr.io/org/myapp-worker:v2.1.0"
  }
}
```

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `app` | string | yes | App name (must exist on the server) |
| `tag` | string | yes | Image tag to deploy (e.g. `sha-abc1234`) |
| `images` | object | no | Per-container image overrides: `{container_name: full_image_ref}` |

### Response: 202 Accepted

```json
{
  "deploy_id": "dpl_01J...",
  "app": "myapp",
  "tag": "sha-abc1234",
  "status": "accepted",
  "preview_url": null
}
```

| Field | Type | Description |
|-------|------|-------------|
| `deploy_id` | string | Unique deploy identifier (use with `GET /v1/deploys/{id}`) |
| `app` | string | App name |
| `tag` | string | Deployed tag |
| `status` | string | Always `"accepted"` on success |
| `preview_url` | string or null | Preview URL for preview deploys; `null` for production |

### Error responses

| Status | Meaning |
|--------|---------|
| 400 | Invalid request body (missing fields, bad JSON) |
| 401 | Missing or invalid `X-Slip-Signature` header |
| 404 | App not found |
| 500 | Internal server error |

## GET /v1/deploys/{deploy_id}

Poll the current status of a deploy. This endpoint is authenticated via **Bearer token** (admin).

### Request

```
GET /v1/deploys/{deploy_id}
Authorization: Bearer <admin-token>
```

### Response: 200 OK

```json
{
  "deploy_id": "dpl_01J...",
  "app": "myapp",
  "tag": "sha-abc1234",
  "status": "health_checking",
  "started_at": "2026-07-05T01:00:00Z",
  "finished_at": null,
  "error": null
}
```

| Field | Type | Description |
|-------|------|-------------|
| `deploy_id` | string | Unique deploy identifier |
| `app` | string | App name |
| `tag` | string | Deployed tag |
| `status` | string | Current deploy status (see status enum below) |
| `started_at` | string (ISO 8601) | When the deploy was accepted |
| `finished_at` | string (ISO 8601) or null | When the deploy reached a terminal state; `null` while in progress |
| `error` | string or null | Error message if the deploy failed; `null` otherwise |

### Status enum

| Status | Terminal | Description |
|--------|----------|-------------|
| `accepted` | No | Deploy request received, queued for processing |
| `pulling` | No | Pulling container images |
| `configuring` | No | Configuring the deployment (networking, secrets) |
| `starting` | No | Starting containers |
| `health_checking` | No | Running health checks (readiness probe) |
| `switching` | No | Switching traffic (blue-green swap) |
| `stopping_old` | No | Stopping old containers (recreate strategy) |
| `removing_route` | No | Removing old route (recreate strategy) |
| `restarting_old` | No | Restarting old containers after failed health check |
| **`completed`** | **Yes** | Deploy succeeded — containers are healthy and serving traffic |
| **`failed`** | **Yes** | Deploy failed — see `error` field for the reason |

Only `completed` and `failed` are terminal states. All other statuses mean the deploy is still in progress.

### Error responses

| Status | Meaning |
|--------|---------|
| 401 | Missing or invalid `Authorization: Bearer` header |
| 404 | Deploy ID not found |
| 500 | Internal server error |

## CLI: `slip deploy --wait`

The `slip deploy` command supports a `--wait` flag that polls `GET /v1/deploys/{id}` until the deploy reaches a terminal state.

```bash
# Fire-and-forget (backwards compatible)
slip deploy myapp sha-abc1234 --secret "$SLIP_DEPLOY_SECRET"

# Wait for completion (default timeout: 10 minutes)
slip deploy myapp sha-abc1234 --secret "$SLIP_DEPLOY_SECRET" --wait

# Wait with custom timeout
slip deploy myapp sha-abc1234 --secret "$SLIP_DEPLOY_SECRET" --wait --wait-timeout 5m

# JSON output (progress events + final record)
slip deploy myapp sha-abc1234 --secret "$SLIP_DEPLOY_SECRET" --wait --json
```

### Exit codes

| Exit code | Meaning |
|-----------|---------|
| 0 | Deploy completed successfully |
| 5 | Deploy failed (see stderr for reason) |
| 6 | Deploy did not reach terminal state within the timeout |

### JSON output shape (`--wait --json`)

The CLI emits one JSON object per line for each state change, plus a final record:

```
{"event":"accepted","deploy_id":"dpl_01J...","app":"myapp","tag":"sha-abc1234"}
{"event":"status_change","deploy_id":"dpl_01J...","status":"pulling"}
{"event":"status_change","deploy_id":"dpl_01J...","status":"starting"}
{"event":"status_change","deploy_id":"dpl_01J...","status":"health_checking"}
{"event":"status_change","deploy_id":"dpl_01J...","status":"switching"}
{"event":"completed","deploy_id":"dpl_01J...","app":"myapp","tag":"sha-abc1234","status":"completed","started_at":"...","finished_at":"..."}
```

On failure:

```
{"event":"accepted","deploy_id":"dpl_01J...","app":"myapp","tag":"sha-abc1234"}
...
{"event":"failed","deploy_id":"dpl_01J...","app":"myapp","tag":"sha-abc1234","status":"failed","error":"[health_check_timeout] ...","started_at":"...","finished_at":"..."}
```

The `error` field carries a SLIP-91 terminal reason tag. Health-related reasons:

| Tag | When | Detail |
|-----|------|--------|
| `[health_unexpected_status]` | Probe received an HTTP response whose status was not in `expect_status` | `expected`, `actual`, `url`, `attempts` |
| `[health_check_failed]` | Transport/timeout — no response ever received | `retries`, `url` |
| `[health_check_timeout]` | Deploy-level hard timeout (`[deploy].timeout`) hit | the configured timeout |

See `docs/health.md` for the full reason taxonomy and probe semantics.

On timeout:

```
{"event":"timeout","deploy_id":"dpl_01J...","timeout_secs":600}
```

## CI Recipe

### Option A: `slip deploy --wait` (recommended)

Requires the `slip` CLI installed in the CI runner. This is the workflow that `slip init` scaffolds.

```yaml
# .github/workflows/deploy.yml
name: Deploy

on:
  push:
    branches: [main]

env:
  APP: myapp
  IMAGE: ghcr.io/org/myapp

jobs:
  deploy:
    runs-on: ubuntu-latest
    permissions:
      contents: read
      packages: write

    steps:
      - uses: actions/checkout@v4

      - name: Set up Docker Buildx
        uses: docker/setup-buildx-action@v3

      - name: Log in to GHCR
        uses: docker/login-action@v3
        with:
          registry: ghcr.io
          username: ${{ github.actor }}
          password: ${{ secrets.GITHUB_TOKEN }}

      - name: Generate image tags
        id: tags
        run: |
          SHORT_SHA="${GITHUB_SHA:0:7}"
          echo "tag=sha-${SHORT_SHA}" >> "$GITHUB_OUTPUT"

      - name: Build and push
        uses: docker/build-push-action@v6
        with:
          context: .
          push: true
          tags: ${{ env.IMAGE }}:${{ steps.tags.outputs.tag }}

      # Install slip CLI (or use a pre-installed runner)
      - name: Install slip CLI
        run: |
          curl -sSfL https://github.com/slip/slip/releases/latest/download/slip-$(uname -m)-linux-gnu.tar.gz \
            | tar xz -C /usr/local/bin slip

      - name: Deploy with wait
        env:
          SLIP_DEPLOY_SECRET: ${{ secrets.SLIP_DEPLOY_SECRET }}
          SLIP_DEPLOY_URL: ${{ vars.SLIP_DEPLOY_URL || secrets.SLIP_DEPLOY_URL }}
        run: |
          slip deploy "$APP" "${{ steps.tags.outputs.tag }}" \
            --server "$SLIP_DEPLOY_URL" \
            --secret "$SLIP_DEPLOY_SECRET" \
            --wait \
            --wait-timeout 10m
```

### Option B: Pure-curl polling (no CLI required)

For CI runners where installing the `slip` CLI is impractical, use this curl-based variant. It supersedes the hand-rolled snippet from the POI Australia field report (§8).

```yaml
# .github/workflows/deploy-curl.yml
name: Deploy (curl)

on:
  push:
    branches: [main]

env:
  APP: myapp
  IMAGE: ghcr.io/org/myapp

jobs:
  deploy:
    runs-on: ubuntu-latest
    permissions:
      contents: read
      packages: write

    steps:
      - uses: actions/checkout@v4

      - name: Set up Docker Buildx
        uses: docker/setup-buildx-action@v3

      - name: Log in to GHCR
        uses: docker/login-action@v3
        with:
          registry: ghcr.io
          username: ${{ github.actor }}
          password: ${{ secrets.GITHUB_TOKEN }}

      - name: Generate image tags
        id: tags
        run: |
          SHORT_SHA="${GITHUB_SHA:0:7}"
          echo "tag=sha-${SHORT_SHA}" >> "$GITHUB_OUTPUT"

      - name: Build and push
        uses: docker/build-push-action@v6
        with:
          context: .
          push: true
          tags: ${{ env.IMAGE }}:${{ steps.tags.outputs.tag }}

      # ── Signed deploy webhook ────────────────────────────────────────────
      - name: Trigger deploy
        id: deploy
        env:
          SLIP_DEPLOY_URL: ${{ vars.SLIP_DEPLOY_URL || secrets.SLIP_DEPLOY_URL }}
          SLIP_DEPLOY_SECRET: ${{ secrets.SLIP_DEPLOY_SECRET }}
        run: |
          PAYLOAD="{\"app\":\"${APP}\",\"tag\":\"${{ steps.tags.outputs.tag }}\"}"
          SIGNATURE=$(echo -n "$PAYLOAD" | openssl dgst -sha256 -hmac "$SLIP_DEPLOY_SECRET" | awk '{print $2}')
          RESPONSE=$(curl -sS -X POST \
            "${SLIP_DEPLOY_URL}/v1/deploy" \
            -H "Content-Type: application/json" \
            -H "X-Slip-Signature: sha256=${SIGNATURE}" \
            -d "$PAYLOAD")
          echo "Deploy response: $RESPONSE"
          DEPLOY_ID=$(echo "$RESPONSE" | jq -r '.deploy_id')
          echo "deploy_id=${DEPLOY_ID}" >> "$GITHUB_OUTPUT"

      # ── Poll until terminal ─────────────────────────────────────────────
      - name: Wait for deploy
        env:
          SLIP_DEPLOY_URL: ${{ vars.SLIP_DEPLOY_URL || secrets.SLIP_DEPLOY_URL }}
          SLIP_TOKEN: ${{ secrets.SLIP_TOKEN }}
        run: |
          DEPLOY_ID="${{ steps.deploy.outputs.deploy_id }}"
          echo "Waiting for deploy ${DEPLOY_ID}..."
          MAX_POLLS=120  # 120 × 5s = 10 minutes
          for i in $(seq 1 ${MAX_POLLS}); do
            RESPONSE=$(curl -sS "${SLIP_DEPLOY_URL}/v1/deploys/${DEPLOY_ID}" \
              -H "Authorization: Bearer ${SLIP_TOKEN}")
            STATUS=$(echo "$RESPONSE" | jq -r '.status // "unknown"')
            ERROR=$(echo "$RESPONSE" | jq -r '.error // empty')
            echo "  [${i}/${MAX_POLLS}] status: ${STATUS}"
            case "$STATUS" in
              completed)
                echo "✓ Deploy completed successfully"
                exit 0
                ;;
              failed)
                echo "✗ Deploy failed: ${ERROR}"
                exit 1
                ;;
              *)
                sleep 5
                ;;
            esac
          done
          echo "✗ Deploy timed out after 10 minutes"
          exit 1
```

> **Note:** The curl variant requires `SLIP_TOKEN` (admin Bearer token) as a GitHub secret for the status polling endpoint, since `GET /v1/deploys/{id}` uses Bearer auth. The deploy webhook (`POST /v1/deploy`) uses the HMAC deploy key (`SLIP_DEPLOY_SECRET`).
